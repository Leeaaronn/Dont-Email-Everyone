<objective>
Prove the reproduction claim before the README is allowed to make it.

Purpose: ROADMAP Phase 7 criterion 5 says `python -m dont_email_everyone.pipeline all` on a fresh
clone reproduces every artifact and figure from the vendored CSV. That is a claim the README makes
about the repository, and `07-CONTEXT.md` records that it "needs verifying in this phase, not
assuming". Nothing in the suite currently runs the whole chain end to end: `tests/test_build_all.py`
runs `ingest` alone, and `tests/test_pipeline.py`'s `analyzed` and `trained` fixtures each seed a tmp
directory with the *committed* outputs of the preceding stage. Every link is tested; the chain is
not. A stage that silently depends on a committed file it does not itself write would pass the whole
suite today and fail on a fresh clone -- which is exactly the reader who matters.

This plan also settles `07-CONTEXT.md` open question 2 and does so for the whole phase, because
criterion 2's regeneration clause and criterion 5 turn out to be one mechanism.

Output: `tests/test_fresh_clone.py`, a measured record of the run, and a written ruling on criterion 2
that plans 07-03 and 07-04 cite rather than re-derive.
</objective>

Perform the reproduction, measure it, and write down what it proved. Change no committed file.

**Before anything:** record `git status --short data/processed reports/figures`. It must print
nothing. Record the same command at the end of the task. If it prints anything at either point, stop
and report it -- `07-CONTEXT.md`'s phase boundary forbids this phase from moving a published number,
and a dirty artifact tree means something already did.

**The run.** Drive it in-process with `config.PROCESSED`, `config.REPORTS` and `config.FIGURES` all
patched onto a fresh temporary tree, exactly as `tests/test_pipeline.py`'s `trained` fixture does,
then call `pipeline.main(["all"])`. Patch all three by name: `FIGURES` is bound to `REPORTS /
"figures"` at import time, so patching `REPORTS` alone leaves figures landing in the committed
directory -- which would both corrupt the working tree and make the figure comparison vacuous.

Do NOT redirect `config.RAW_CSV` or `config.CHECKSUM_FILE`. The vendored CSV and its recorded
SHA-256 are the INPUT criterion 5 names; a run that does not read them proves nothing. Assert the
temporary tree is empty before the run so every file found afterwards is one this run wrote.

Record the wall-clock duration. `train()` is dominated by eight refit permutation nulls at 200
shuffles each and `tests/test_pipeline.py` describes it as taking several minutes; the total is the
number Task 2's module docstring has to state honestly, and it is the number that decides whether
this is one `slow` test or a documented manual procedure.

**The diff.** Compare three things and report each as a measurement, not a verdict:

1. Artifact name set. `{p.name for p in produced_processed.iterdir()}` against the committed
   `{p.name for p in config.PROCESSED.iterdir()}`. Report both directions of the set difference
   separately. A committed file the pipeline does not write is a different and worse failure than a
   produced file that was never committed, and a symmetric-difference count collapses them.
2. Figure name set, the same way, against the 19 committed PNGs.
3. Numeric agreement. Compare the produced `manifest.json` against the committed one field by field
   over the whole document, not just the headline block, and report the worst absolute and worst
   relative deviation over every float, naming the field each came from. Do the same for
   `ate.json` and `model.json`. Then compare the Parquet artifacts with
   `pandas.testing.assert_frame_equal` and report which, if any, needed a tolerance.

   Expect exact equality. Every forest is fit at `random_state=20260902` with `n_jobs=1` and every
   bootstrap and permutation seed is recorded in the artifacts, so exact is the designed outcome. If
   anything is inexact, report the field, the magnitude and the direction before deciding anything --
   a tolerance in Task 2 must be derived from this measurement the way
   `tests/test_pipeline.py::QINI_RECOMPUTE_TOLERANCE` was derived from its own, never guessed to make
   a test pass.

Do NOT compare PNG bytes. `tests/test_reports.py`'s module docstring already records why: matplotlib
embeds run-specific metadata, so two runs of the same code on the same data produce different bytes,
a byte comparison fails on correct code, and the usual repair is to delete the assertion. Names and
non-trivial byte size are the honest assertions for a raster.

**If the run fails or the sets disagree:** stop and report. Do not repair the pipeline. This phase
documents finished work, and a criterion-5 failure is a finding about the pipeline that belongs in
front of the user, not a defect for a documentation plan to quietly fix.

**The ruling on criterion 2.** `07-CONTEXT.md` open question 2 asks whether criterion 2's "verified
by regenerating artifacts and diffing rather than by hand-copying" demands an actual regeneration
inside this phase. Write the ruling below into the summary as the phase's settled reading, with the
reasoning, so 07-03 and 07-04 cite it instead of re-deriving it:

> Criterion 2 has two halves and they are discharged by two different mechanisms.
>
> *"Every number in the README traces to a committed artifact"* is discharged by the D-05
> identity test in plan 07-03. It derives each README literal from `manifest.json` at run time
> through the app's own `display_value`, so the test contains no copy of any number and a stale
> README fails on every `pytest` invocation.
>
> *"verified by regenerating artifacts and diffing rather than by hand-copying"* is a claim about
> `manifest.json`, not about the README. Pinning the README to the manifest is worth nothing if the
> manifest is itself a hand-maintained file, and the criterion's wording is precisely the guard
> against that. So yes -- the regeneration is required, and it is this plan.
>
> The two criteria share one mechanism, which is why this run is performed once and both
> criterion 2 and criterion 5 cite it. The completed chain is:
>
>     README literal
>       -> (07-03's provenance test, every run) manifest.json scalar
>       -> (test_artifacts.py::test_headline_reproduces_from_committed_columns) scored_holdout.parquet
>       -> (this plan's test) the vendored CSV and the committed code
>
> Every link is mechanical. No link is a human transcription. That is the whole of what criterion 2
> asks for.
