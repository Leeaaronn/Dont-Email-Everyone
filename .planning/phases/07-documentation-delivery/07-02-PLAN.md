<objective>
Make the result survive a cold app.

Purpose: ROADMAP Phase 7 criterion 4's second half. Streamlit Community Cloud sleeps an app after 12
hours without traffic, and the first reviewer to open this repository is likely to be the visitor who
resets that clock. The README already explains the sleep page and the one-click wake -- but an
explanation is not a result. A static image of the app's key output is the standing mitigation, and
`07-CONTEXT.md` records it as the reason ROADMAP Phase 6 criterion 5 deliberately does not duplicate
the cold-start check.

D-06 asks for the headline block plus the first policy curve, at the 1100 px display cap, legible.
This plan captures them, records how, and puts the honest tests behind them -- including an explicit
statement of what cannot be tested, rather than a weak test dressed up as coverage.

Output: two committed PNGs, a written capture recipe, and the presence half of `tests/test_readme.py`.
</objective>

3. **Window width.** `FIGURE_DISPLAY_WIDTH_PX = 1100` is a CAP, not a floor -- `st.pyplot` clamps to
   the parent container, so a narrow window makes the figure narrower than 1100 and the capture no
   longer shows what the cap delivers. State the minimum viewport width that makes the cap bind
   (measure it: widen until the rendered figure stops growing, then record that width), and state
   that the capture must be taken at or above it.
4. **Crops.** Two images, bounded by element rather than by pixel:

     listed in `<interfaces>` must be inside it, including both verdict lines.

     and is not, detectable", including its legend and its `curve_caption` line. The caption is not
     optional: it carries the zero-by-construction explanation for the orange square, and a figure
     cropped away from it reads as a bug.
5. **What must not be in frame.** No browser chrome, no address bar, no bookmarks bar, no tab strip,
   no OS window title, no taskbar, no notification. This repository is public. A URL bar can carry a
   `file:///C:/Users/<name>/` path and a window title can carry a machine name; neither belongs in a
   portfolio artifact, and neither is recoverable once pushed.
6. **The capture record.** At capture time, record in this document: the date, the source used, the
   viewport width, and `git rev-parse HEAD` for `streamlit_app.py` (`git log -1 --format=%H --
   streamlit_app.py`). That SHA is what makes staleness checkable by hand.

Then write the staleness section, and write it honestly. The finding to record, in this repository's
voice:

> **There is no honest automated test that these images are current.**
>
> Detecting a stale screenshot means reading the numbers out of a raster, and reading numbers out of
> a raster means OCR, which means a dependency this project's library constraint does not permit and
> would not want. Every cheaper substitute was considered and each is a test that fails on correct
> code:
>
> - *Compare the image's commit date against `streamlit_app.py`'s.* Fails on a comment-only edit to
>   the app, which changes no pixel. `tests/test_reports.py` already recorded what happens to a test
>   that fails on correct code: it gets deleted, and the artifact ends up with no coverage at all.
> - *Compare image bytes against a recorded checksum.* Pins nothing about the content and fails the
>   moment anyone recompresses the file.
> - *Assert the image's dimensions.* True of any image of that size, including a stale one.
>
> What is done instead is a coupling rather than a detector. The README restates, in text
> immediately beside each image, the numbers that image shows -- and those restated numbers are
> derived from `manifest.json` at test time by
> `tests/test_readme.py::test_readme_headline_numbers_trace_to_the_manifest` (plan 07-03). If a
> published number moves, that test fails, and whoever repairs the caption is standing in front of
> the image with the old number in it. The image is not watched; the claim beside it is, and the
> repair path runs through the image.
>
> The standing manual check, which takes one command:
>
>     git log --oneline <recorded-capture-sha>..HEAD -- streamlit_app.py
>
> Empty output means the app's source has not moved since capture. Non-empty output means read the
> commits and decide whether any of them changed what is in frame. `tests/test_readme.py` asserts
> only that the recorded SHA is a real commit in this repository's history -- it proves the record is
> REAL, not that it is CURRENT, and that distinction is the whole of what it claims.

Commit as its own atomic commit, with a body explaining why a procedure document exists for what
looks like a one-off screenshot: the image is a published claim, and an unreproducible published
claim is one nobody can correct.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer's screen -> public repository | a screenshot carries whatever was in frame, permanently and irrevocably once pushed |
| deployed app -> committed image | the image makes a claim about numbers no test can read back out of it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | Information Disclosure | `docs/*.png` | mitigate | explicit exclusion list in the recipe (no address bar, bookmarks, tab strip, window title, taskbar, notifications) and a blocking human check on both images before they are saved -- a `file:///C:/Users/<name>/` path or a machine name in a window title is not recoverable after a push to a public repo |
| T-07-05 | Spoofing | a screenshot showing numbers the project no longer publishes | mitigate | the README restates the imaged numbers in text beside each image and 07-03's provenance test derives those from `manifest.json`; the repair path for a moved number runs through the image. No detector on the raster is claimed -- see `docs/SCREENSHOT-CAPTURE.md` |
| T-07-06 | Repudiation | an unreproducible capture | mitigate | `docs/SCREENSHOT-CAPTURE.md` records source, viewport width, zoom, page state, crop bounds and the capture commit SHA; the SHA is asserted to be a real commit |
| T-07-07 | Tampering | capturing at a moved depth control | mitigate | the recipe fixes the control at its default 20% anchor and the human check confirms all six headline numbers before capture; a capture at another depth shows numbers `manifest.json` does not publish |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | no installs. A headless-browser dependency was considered and rejected as forbidden by `CLAUDE.md`'s library constraint, which is why Task 2 is a human action |
