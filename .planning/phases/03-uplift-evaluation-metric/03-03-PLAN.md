Add `qini_plot` to `dont_email_everyone/plots.py` — the figure factory ROADMAP criterion 4 requires —
and its test cluster in `tests/test_plots.py`.

Purpose: the single most common way a hand-rolled Qini figure lies is drawing the random-targeting
baseline as a bare `y = x` diagonal instead of the chord from `(0,0)` to `(1, ATE)` computed from the
data. Radcliffe's own text defines the baseline as the chord; PITFALLS.md Pitfall 8.2 names the
diagonal as an error. This plan makes the chord's endpoints machine-checkable by reading the drawn
line's coordinates.

Output: one new factory in `plots.py`, and its case cluster in `tests/test_plots.py`. **No PNG is
committed** (D-09).

<discretion_resolutions>
- **The figure factory lives in `dont_email_everyone/plots.py`**, not a new module (RESEARCH.md
  §Q8.4). Three concrete reasons, none stylistic: (1) `plots.py` already sets `matplotlib.use("Agg")`
  on the line immediately before the pyplot import, and 02-05 recorded that ordering as load-bearing
  — a second module importing pyplot would need a duplicate of that line, and the duplicate is the
  one someone eventually deletes; (2) `test_plots_module_never_renders` and
  `test_plots_module_writes_nothing` are whole-module boundary tests that a new factory inherits for
  free and would have to be re-authored elsewhere; (3) `love_plot`'s pinned axis limits are the
  direct precedent for keeping a computed reference line on the canvas.
- **No committed figure** (D-09). A synthetic Qini curve sitting beside Phase 2's real
  `love_plot.png` and `ate_forest.png` could be mistaken for a result. The first committed uplift
  figure is Phase 4's, drawn on real holdout scores.
</discretion_resolutions>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-10 | Denial of Service | pyplot's global figure registry | mitigate | An unclosed or unhanded `Figure` stays registered forever; matplotlib warns once more than 20 accumulate, and a loop building several figures is exactly where that happens. The factory returns the `Figure` and closes nothing — the caller owns both `savefig` and `close`. Pinned by `test_qini_plot_leaves_no_stray_figures` and by the existing whole-module `test_plots_module_writes_nothing`. |
| T-03-11 | Information Disclosure | `plots.py` filesystem surface | mitigate | The module writes nothing. Already enforced by the existing `test_plots_module_writes_nothing` (chdir + empty-dir assertion), which Task 2 extends to build a `qini_plot` figure so the assertion covers the new factory. |
| T-03-12 | Repudiation (by analogy — the project's real reputational risk) | the drawn random-targeting baseline | mitigate | A `y = x` diagonal makes an ordinary curve look like it beats random targeting. The chord is computed from `qini[-1]` and its drawn endpoints are asserted by reading Line2D data, with a companion assertion that `qini[-1] != 1.0` so the check cannot be vacuous. Axis limits are pinned rather than autoscaled so the chord cannot drift off canvas. |
| T-03-13 | Tampering | `_UNIT_AXIS_LABEL` regression | mitigate | Phase 2's forest-plot labels are asserted at `tests/test_plots.py:291-298`. This plan adds `_QINI_AXIS_LABEL` beside them rather than editing them, and an acceptance criterion greps the diff to prove no existing label string was removed. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No package is installed. Matplotlib 3.11.1 is already pinned at an exact `==` version in the committed `requirements.txt`. RESEARCH.md's Package Legitimacy Audit table is empty by construction. |
