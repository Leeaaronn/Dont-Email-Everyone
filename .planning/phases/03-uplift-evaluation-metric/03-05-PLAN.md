  <action>
Add `bootstrap_indices(treatment, n_resamples: int = 500, seed: int = 20260902) -> np.ndarray` to
`evaluation.py`. Returns a 2-D `(n_resamples, n)` array with `dtype=np.int32`, where row `r` is one
complete arm-stratified resample of the row positions `0..n-1`.

**The algorithm is position-preserving, not block-layout.** Create one `np.random.default_rng(seed)`
outside the loop — `coverage.py:175-184`'s precedent, so the whole matrix is a single reproducible
stream. For each arm value in `(1, 0)`, take `pos = np.flatnonzero(treatment == value)` and fill
`out[:, pos]` with `rng.choice(pos, size=(n_resamples, pos.size), replace=True)`. Each column is
therefore drawn from **its own arm's** index pool, so column `j` always resamples from the same arm
as row `j`.

**Docstring must state the invariant and the two consumption rules:**
  - The invariant, in code form so it is greppable: `np.array_equal(treatment[out[r]], treatment)`
    holds for every `r`. That is what lets Phase 5's policy-value CI and Phase 6's revenue band index
    **any** per-row array with `out[r]` without knowing a block layout. Name the rejected
    alternative — writing all treated draws into the first `N_t` columns and all control draws after
    — and say it stratifies correctly but imposes a column layout every downstream consumer has to
    know; measured cost is identical, so position-preservation is free.
  - **`int32` is deliberate.** 170 MB at R=1000 / n=42,613 instead of 341 MB, against
    `np.iinfo(np.int32).max` of 2,147,483,647 versus a maximum index of 42,612 — five orders of
    magnitude of headroom, on a fixed 64,000-row vendored CSV that will never grow. Add a guard
    raising `ValueError` when `treatment.size > np.iinfo(np.int32).max`, so the choice is checked
    rather than assumed.
  - **The matrix is in-process reuse infrastructure, NEVER a persisted artifact.** FEATURES.md says
    "compute the resample indices once, persist them, reuse", which reads as an instruction to write
    them to disk; the correct reading is *persist the derived band columns*. Committing an 85-170 MB
    binary blob to git would be a serious repo-hygiene error. Also state that the Phase 6 app must
    never call this function — it consumes precomputed band columns, because 170 MB is a material
    fraction of Streamlit Community Cloud's ~690 MB envelope.

**Guards** (`if`/`raise`, never `assert`, message names the observed value): `n_resamples >= 1`;
`treatment` contains only 0 and 1; both arms non-empty, naming the empty arm; the int32 ceiling
above. Reuse the shared validator from plan 03-01 where it applies rather than duplicating checks.
  </action>
