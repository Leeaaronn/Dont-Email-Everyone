<objective>
Extend `tests/conftest.py`'s `synthetic_frame` factory with a heterogeneous treatment effect, and use
it to build the statistical invariants ROADMAP criterion 2 names: random score near zero, oracle
score strongly positive, negated score non-positive, plus D-03 tier 2's tie-heavy row-order wobble.

Purpose: the existing fixture adds a **constant** `effect` to treated spend, so every row has the
same individual effect and there is nothing for a ranking to discover — an "oracle" score on that
frame is a random score. Without heterogeneity the oracle invariant is untestable, and the oracle
invariant is what proves the metric can tell a good ranking from a bad one at all.

Output: a backward-compatible `hetero` parameter on `synthetic_frame`, and the statistical section of
`tests/test_evaluation.py`.
</objective>

<hazard>
## The RNG draw-order hazard — read this before touching conftest.py

`synthetic_frame` consumes **one** `np.random.default_rng(seed)` stream in strict draw order:
`treatment` (line 91) then `recency`, `history`, `zip_code`, `channel`, optionally one imbalance
draw, the `spend` gamma (line 121), the `visit` binomial, the `conversion` binomial — **and then
three more `rng.binomial` calls inside the `pd.DataFrame(...)` constructor itself** for `mens`,
`womens` and `newbie` at lines 132-135.

Inserting a `u = rng.normal(size=n)` draw anywhere in that sequence shifts every subsequent draw and
silently breaks the `hetero=0.0` bit-for-bit backward compatibility RESEARCH §Q4 requires — which
would in turn change `mens`, `womens`, `newbie`, `visit` and `conversion` in every existing Phase 1
and Phase 2 test that uses this fixture.

**Both safe options are acceptable; this plan requires you to pick one and prove it:**
  (a) draw `u` from a *separate* stream, `np.random.default_rng(seed + 1)`, so the primary stream is
      untouched regardless of `hetero`; or
  (b) draw `u` only inside an `if hetero:` branch placed *after* every other draw in the function,
      including the three inside the DataFrame constructor.

Option (a) is preferred — it keeps every column except `spend`, `_tau` and `_u` independent of the
`hetero` value, which makes the backward-compatibility proof a one-liner. Whichever is chosen, the
proof is `assert_frame_equal(synthetic_frame(), synthetic_frame(hetero=0.0))` on the shared columns.
</hazard>
