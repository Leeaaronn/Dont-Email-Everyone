<objective>
Add the `policy` subcommand and write the four committed artifacts the app and the README
will read.

Purpose: criterion 4 requires the committed artifacts to be small, format-stable, and
sufficient to reproduce every headline number with arithmetic alone — no model file. The
estimator makes that free: the headline collapses to
`weight * (sum of treated outcome in the top k - sum of control outcome in the top k)`, which
a reader can check on a calculator from `scored_holdout.parquet`. `manifest.json` does not
exist yet; ROADMAP criterion 4 and Phase 7 criterion 2 both name it, and this phase creates it.

D-08a governs how the headline is framed. The vs-everyone contrast is minus the incremental
outcome of the bottom (1-k), so at zero cost it cannot be positive on a data set whose ATE is
positive on every outcome — swept across three outcomes, three rankings and 101 grid points,
not one k produces a CI excluding zero. Both criterion-1 differences are computed and
written. Neither is the headline. The headline is targeted top-k versus a RANDOM send of the
same size, which is the contrast D-06's own sentence describes, and the zero-cost caveat
travels with it.

Output: `pipeline.policy()`, the `policy` subcommand, and four committed artifacts.
</objective>

**The one draw.** Build ONE index matrix for the whole phase: integer codes of `segment` over
all 32,001 holdout rows with the levels ordered (control, mens, womens), passed to
`evaluation.stratified_indices` at `BOOTSTRAP_BAND_RESAMPLES` and seed 20260902 with that

per arm: the shared control gets one draw per replicate, which is criterion 2, and three
intervals from the same draws are jointly valid where three independently drawn intervals
quietly disagree. Derive both frame sizes from the data, never as literals.

**What is computed.** Three rankings by three outcomes, all on the womens+control frame:

  - `uplift_womens_visit` — D-01's headline ranking, locked on Phase 4 evidence (holdout

comment saying that is why.

For each (ranking, outcome): `policy_value_curve` for the point estimates and
`policy_value_band` for the banded quantities, both at `weight=evaluation.POLICY_WEIGHT` and
`n_grid=evaluation.BAND_GRID_POINTS`, passing the shared `indices`.

**The cost exhibit (D-09).** For the headline ranking on the spend outcome only, run
`economics.cost_margin_sweep` over a `c/m` grid. Choose the grid so the measured behaviour is

stored as explicit rows flagged `illustrative = True`, never adopted as defaults (D-10).

**Artifacts.** Four, assembled fully in memory, then written with four explicit statements —
never a loop.

  - `policy_curve.parquet` — long form, one row per (ranking, outcome, k): `ranking`,
    `outcome`, `k`, `n_targeted`, `v_pi`, `v_all`, `v_none`, `delta_none`, `delta_all`,
    `delta_random`, `per_targeted`, `weight`, `n_frame`. Long rather than wide, so a later
    ranking appends rows instead of altering the schema — `permutation_null.parquet`'s
    precedent.
  - `policy_bands.parquet` — one row per (ranking, outcome, contrast, k) with `lo` and `hi`
    as TWO float columns. Never a tuple-valued column.
  - `cost_sweep.parquet` — one row per c/m ratio: `cost_over_margin`, `k_star`,
    `profit_at_k_star`, `profit_at_k_1`, plus the illustrative rows carrying their own
    `cost_per_email` and `gross_margin`.
  - `manifest.json` — the scalar block, same grain rule as `ate.json`: anything whose grain
    is not tabular lands here. Structure it as:

        generated_by, generated_from (the input artifact names),
        frame: {n_customers, n_targeted, capacity_k, weight, ranking, arm, outcomes}
        headline: {
          contrast: "vs_random_send_of_the_same_size",
          per_outcome: { visit | conversion | spend : {
              total, total_lo, total_hi,
              per_targeted, per_targeted_lo, per_targeted_hi,
              vs_nobody, vs_nobody_lo, vs_nobody_hi,
              vs_everyone, vs_everyone_lo, vs_everyone_hi,
              vs_random, vs_random_lo, vs_random_hi } },
          caveat: "<the zero-cost caveat, in full>",
          reproduce: "<the two-term subtraction, written out>"
        }
        cost_exhibit: {k_star_at_zero_cost, first_breakpoint, k_star_at_ratio_1_5,
                       n_distinct_k_star, illustrative_pairs}

    Two hard rules on this block, both testable:

      1. **No `unproven_`-prefixed ranking may contribute a number to `headline`** (D-03).
         Sensitivity numbers live under `sensitivity`, keyed by the artifact column name so
         the label is inseparable from the number.
      2. **The `caveat` string is mandatory and stated in full**, not abbreviated: with
         genuinely free email the correct action is to email everyone; this result is about
         spending a fixed budget well. D-08a requires it wherever the headline appears, and
         the manifest is the first place it appears.

    `headline.reproduce` carries the literal arithmetic a reader can run — the ranking
    column, the seed, the `int(n*k)` rule, and `weight * (sum_treated - sum_control)` — so
    criterion 4 is satisfied by a sentence in the artifact and not only by a property of the
    code.

**D-11 is a hard boundary here.** Every dollar figure is on the evaluation frame as measured,
