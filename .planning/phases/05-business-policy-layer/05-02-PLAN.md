<objective>
Generalize Phase 3's resample engine to any number of arms without moving a single cell of
the matrix it already produces.

Purpose: criterion 2 requires that the shared control group be resampled ONCE per replicate
so the correlation between the two arms survives into the difference. D-14 established from
the code that `bootstrap_indices` already satisfies this for the womens-only policy, and
that it *raises* on a three-valued column — so D-05's cross-arm work has no engine. Building
one binary matrix per arm is precisely the bug criterion 2 exists to prevent: the shared
control would get two different draws in the same replicate.

Output: `evaluation.stratified_indices`, with `bootstrap_indices` reduced to a validated
wrapper that delegates, and a regression test proving the delegation changed nothing.
</objective>

    def bootstrap_indices(treatment, n_resamples: int = 500, seed: int = 20260902):
        # ... 1-D guard, empty guard, n_resamples guard, int32-ceiling guard,
        #     then _guard_treatment(treatment)
        rng = np.random.default_rng(seed)
        out = np.empty((n_resamples, treatment.size), dtype=np.int32)
        for value in (1, 0):                      # <-- LOAD-BEARING ORDER
            pos = np.flatnonzero(treatment == value)
            out[:, pos] = rng.choice(pos, size=(n_resamples, pos.size), replace=True)
        return out

  <action>
Add to `evaluation.py`, immediately above `bootstrap_indices` so one draw engine and its
wrapper read as one unit:

    def stratified_indices(labels, n_resamples: int = BOOTSTRAP_BAND_RESAMPLES,
                           seed: int = 20260902, *, level_order=None):

Contract, mirroring `bootstrap_indices` clause for clause:

  - Accepts 2 or more distinct levels. `labels` may be any integer-coded 1-D array.
  - `level_order` is the sequence in which levels consume the RNG stream. When `None`,
    default to `np.unique(labels)` ascending. When given, it must be a permutation of the
    observed levels or a `ValueError` is raised naming both sets.
  - `int32`; one `np.random.default_rng(seed)` stream seeded ONCE outside the loop, exactly
    as today.
  - Position-preserving: fill each level's columns from that level's own index pool.
  - Never persisted. Carry across the "IN-PROCESS REUSE INFRASTRUCTURE" paragraph from
    `bootstrap_indices`' docstring by reference rather than duplicating it, and record the
    measured size: `(500, 32001)` int32 is 64 MB and builds in about 0.13 s, against
    Streamlit Community Cloud's ~690 MB envelope.

**THE HAZARD, and the whole reason this is a plan and not a refactor.** The existing loop
is `for value in (1, 0)` — treated arm FIRST. `np.unique` returns ascending order, so a
naive generalization consumes the RNG stream in the opposite order and changes
approximately 99.99% of the matrix cells. Every band Phase 3 committed would move, silently.
Therefore:

  - `bootstrap_indices` keeps its exact signature, keeps all five of its guards including
    `_guard_treatment` (so a 3-valued column still raises its Pitfall-1 message from the
    wrapper, not from the general engine), and delegates with an explicit
    `level_order=(1, 0)`.
  - Write the reason for that literal `(1, 0)` in a comment directly above the delegation,
    naming the measured consequence of reversing it, so a future reader cannot read it as
    an arbitrary ordering.
  - Do NOT move, reword or delete `bootstrap_indices`' existing docstring. Add one
    paragraph recording that the draws now come from `stratified_indices` and that a
    regression test pins bit-identity.

Add a docstring paragraph to `stratified_indices` recording the project-wide draw decision
this phase makes: **Phase 5 and Phase 6 use ONE three-level matrix over all 32,001 holdout
rows** as the single project-wide draw. Because it is position-preserving, masking its
columns by the original `segment` yields exactly the womens+control columns and exactly the
mens+control columns every replicate, with the control columns identical between the two
masks. State also, so it is a decision and not a surprise, that a three-level matrix
consumes the RNG stream differently from a two-level one, so the womens draws inside it are
NOT the draws `bootstrap_indices(womens_treatment, 500, 20260902)` produces — the phase picks
one and uses it everywhere. Phase 4's already-committed Qini figures are left alone: their
seed is recorded and their bands are figures, not persisted columns.

Do not add a second `argsort` anywhere; `test_evaluation_module_has_exactly_one_sort` counts
executable occurrences and must keep passing at exactly 1.
