<objective>
Build the app's spine: the read, the guard, the render helper and every control — and pin the four
properties criterion 4 is actually about.

Purpose: this is where the phase's structural guarantees are established, before any number reaches
the screen. `render()` is the only place `st.pyplot` appears, which turns "every figure is closed"
from a discipline into a count. The load is cached and ROOT-anchored so it works under Community
Cloud's runtime. The capacity control snaps to the committed 101-point grid **minus `k = 0.0`**,
because `economics.emails_at_capacity(21347, 0.0)` raises `ValueError` and a slider offering all 101
points crashes the app at its leftmost position — a defect averted, not a tidiness preference.

The criterion-4 leak test is the one thing in this phase most likely to be written wrong.
06-RESEARCH built a deliberately leaking app and drove it through 8 `AppTest` reruns: the script
printed `fignums=[1, 2, 3]` from inside itself while the test thread observed `[]` every time,
because Streamlit's script runner calls `plt.close("all")` after every rerun. **An `AppTest` figure
count assertion is a test that cannot fail.** This plan writes the two tests that can.

Output: a runnable `streamlit_app.py` with its title, its controls and its infrastructure; the
criterion-4 test set; and an app-layer network sweep that leaves both package sweeps unweakened.
</objective>
