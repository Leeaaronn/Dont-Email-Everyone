# Phase 6 — UI Design Contract

> Visual and interaction contract for the Streamlit app. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. Consumed by the planner (task text), the executor (source of truth while
> implementing) and the UI auditor (retroactive comparison).

**Scope note.** This is a Streamlit app, not a web frontend. `CLAUDE.md`'s library allowlist is hard:
there is no CSS framework, no component library, no design-token file and no custom CSS available as
a dependency. The design vocabulary is **Streamlit 1.63.0's own widgets plus the committed
`plots.py` matplotlib factories**. Every clause below is written in those terms. Nothing here
introduces a package, and nothing here overrides a figure the 05-08 legibility checkpoint approved.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — no shadcn, no component library, no registry. No `components.json`, `tailwind.config.*`, `postcss.config.*` or `package.json` exists in this repo (verified 2026-09-10). |
| Preset | not applicable |
| Component library | **Streamlit 1.63.0 built-in widgets only.** Allowed element set is enumerated in `## Allowed and Forbidden Element Set`. |
| Chart library | **`dont_email_everyone.plots` factories over matplotlib 3.11.1.** The app calls `policy_curve_plot` and `cost_sweep_plot` and draws nothing itself (D-04). |
| Icon library | **none.** No icon set, no emoji, no `:material/…` shortcode. A portfolio piece read by a technical reviewer earns nothing from decoration, and an emoji in a metric label is an untestable glyph in a repo whose discipline is that claims are checkable. |
| Font | **Streamlit theme default** (the built-in sans stack). Not overridden — overriding needs either a theme font file or custom CSS, and neither is on the allowlist. Figure type is matplotlib's default family at the point sizes `plots.py` already pins. |
| Custom CSS | **FORBIDDEN.** `st.markdown(..., unsafe_allow_html=True)` must not appear in the app. Every hierarchy need in `## Typography` is met by `st.title` / `st.subheader` / `st.metric` / markdown bold / `st.caption` / `st.container(border=True)`. An `unsafe_allow_html` block would also be a second way to express emphasis that the figures already own, which is the same argument D-04 makes against a second chart implementation. Checkable: the token `unsafe_allow_html` appears 0 times in the app source. |

### Theme configuration — `.streamlit/config.toml`

This file is a required deliverable (06-VALIDATION Wave 0) because `browser.gatherUsageStats`
defaults to `True` and a default deployment therefore phones home every session, which criterion 4
forbids. The theme keys below ride along in the same file and are this contract's:

```toml
[browser]
gatherUsageStats = false

[client]
toolbarMode = "viewer"

[theme]
base = "light"
primaryColor = "#1f4e79"
```

- `base = "light"` is **load-bearing, not cosmetic.** The three matplotlib figures are drawn on a
  white canvas. Without a pinned base, a reviewer whose browser prefers dark mode gets dark app
  chrome wrapped around three white rectangles, and the hatched covers-zero spans (`#f0f0f0` face on
  a white axes face) sit inside the brightest region on a dark page — which demotes exactly the
  encoding 05-08 approved as load-bearing evidence.
- `primaryColor = "#1f4e79"` is `plots._POLICY_BAND_COLOUR`, so Streamlit's widget accent is the same
  blue as the policy curve. Streamlit's stock accent is a red (`#FF4B4B`); red widget chrome sitting
  beside a "not detectable" verdict line reads as an alert about a defect rather than as a finding,
  which is the specific misreading this phase exists to prevent.
- **Verification obligation:** `gatherUsageStats = false` is criterion-4 mandatory. The three theme
  keys are this contract's preference — the executor must confirm each key name against the installed
  `streamlit==1.63.0` at Wave 0 and **drop** any key that version does not accept rather than guess a
  replacement.

## Spacing Scale

**Streamlit exposes no px spacing without custom CSS, and custom CSS is forbidden above. No pixel
value is therefore declared, and the "multiples of 4" rule is not applicable to the app chrome.** The
spacing contract is instead the ordered separator vocabulary below, which is checkable by source scan
and by AppTest element order rather than by inspecting computed styles.

| Token | Artist | Usage |
|-------|--------|-------|
| `group` | `st.container(border=True)` | The headline block only. Exactly **one** bordered container exists in the app, and it is the D-07 block. A second border would create a competing emphasis. |
| `section` | `st.divider()` | Between main-body sections **that have no border between them**. Exactly **3** dividers — after the curves, after the contrasts table, after the assumptions section. *(Amended 2026-09-10 at the 06-07 checkpoint. The original read "Between the five main-body sections. Exactly **4** dividers (after the headline block, after the curves, after the contrasts table, after the assumptions section)." The reviewer asked for the gap between the headline block and the first chart to be tightened; Streamlit exposes no pixel spacing without the custom markup this contract forbids, so element count is the only lever available, and the divider after the headline block is the one element in that gap whose work is already being done — the headline block is the app's only bordered container, and a box edge is a harder boundary than a rule immediately beneath it. The other three separate sections with no border between them, which is both the argument for keeping them and the argument for dropping that one.)* |
| `heading` | `st.subheader` | Opens each section after the first. Exactly **3** subheaders. |
| `caption` | `st.caption` | Sits directly under the thing it explains. Never used as a heading. |
| `sidebar` | `st.sidebar` | All controls. Separates control from argument without a layout primitive. |

Exceptions and inherited numeric spacing:

- **`st.columns` is FORBIDDEN in the main body.** Two reasons, both checkable. (1) D-07's adjacency
  requirement is asserted by index over flat document order — 06-RESEARCH verified that iterating
  `at.main` yields elements in document order, and a column block interposes a container between the
  headline metric and its qualifier. (2) Side-by-side figures would break the vertical narrative
  order `## Layout Contract` fixes. Permitted in `st.sidebar` only, for the cost/margin pair.
- **Figure geometry is inherited and must not be overridden.** `policy_curve_plot` and
  `cost_sweep_plot` both build at `figsize=(8.0, 5.6)` with `title` padded at `pad=28` (which is a
  multiple of 4, and is the only numeric spacing value in the whole contract). The app passes **no**
  `figsize`, `dpi`, `pad`, `fontsize` or `rcParams` layout override to either factory.
- **One global rcParam is set, and only this one:** `matplotlib.rcParams["figure.dpi"] = 150`,
  immediately after `matplotlib.use("Agg")` and before any pyplot import. 150 is the repo's committed
  figure convention (`pipeline.py` passes `dpi=150` to every `savefig`). It changes raster resolution
  only, not inches, so font point sizes and layout are untouched and the committed PNGs are
  unaffected (the app never saves a figure).

## Typography

Streamlit supplies the app's px sizes from its theme and they cannot be set without forbidden CSS.
The typography contract is therefore **which artist carries which role**, plus the matplotlib point
sizes already pinned in `plots.py`, which the app inherits unchanged.

| Role | App artist | Figure equivalent (pt, inherited) | Weight | Used exactly |
|------|-----------|-----------------------------------|--------|--------------|
| Display | `st.title` | — | bold (theme) | 1× — the app title |
| Heading | `st.subheader` | figure `title`, stepped `_TITLE_SIZES = (12.0, 11.0, 10.0, 9.5, 9.0, 8.0, 7.0)` by `_fit_titles` | bold (theme) | 3× — one per section after the headline block |
| Emphasis / number | `st.metric` | — | bold (theme) | **3×, and only 3×** — spend, visits, `k*` |
| Body | `st.markdown` | axis labels (matplotlib default 10.0) | regular + **bold** | as enumerated in `## Layout Contract` |
| Caption | `st.caption` | legend `fontsize=7.5`; cost-sweep annotations `fontsize=7` | regular | one per displayed number or figure |

Exactly **two weights** are in play: regular, and bold via markdown `**` / the theme's own heading and
metric weights. No third weight exists to reach for, which is a property of the stack rather than a
rule to keep.

**Formal exemption — the inherited matplotlib point sizes are out of scope for a "max N type sizes"
rule.** The stepped `_TITLE_SIZES` tuple above, the 7.5pt legend and the 7pt cost-sweep annotations
are **not introduced by this contract**. They are inherited unchanged from the `plots.py` factories
whose legibility the 05-08 checkpoint explicitly approved, and they are unreachable from here:
Streamlit exposes no typographic control without `unsafe_allow_html`, which this contract forbids,
and restyling `plots.py` would alter the four committed PNGs, which D-06 forbids on pain of a
byte-identity test failure. A future auditor comparing this contract against a generic frontend
checklist should count the **Streamlit-side** roles in the table above against that kind of rule and
treat the matplotlib column as a record of what was inherited. `layout="wide"` is the one pre-approved
remedy if the UI legibility checkpoint finds the legend too small at ~730 CSS px; shrinking the
figures or editing `plots.py` is not.

*(2026-09-10: **that remedy was invoked and applied.** The 06-07 checkpoint reviewer found the
six-entry legend overlapping the curve at centred width and reported after the switch: "Wide layout
fixed the legend overlap — keep it." `plots.py` was not touched, no figure was shrunk, no legend
entry was dropped, and `git status --short reports/figures dont_email_everyone/plots.py` is empty.
See `## Layout Contract`.)*

Rules, each checkable:

- **`st.metric` is the app's reserved emphasis artist and appears exactly three times.** A fourth
  `st.metric` is a fourth number claiming headline weight, and the only three numbers entitled to it
  are the two halves of the D-03 pair and `k*` (whose own label carries its assumptions — see below).
  Source scan: `st.metric(` occurs exactly 3 times.
- **`st.metric(delta=…)` is FORBIDDEN.** Streamlit renders `delta` as a green-or-red arrow. An arrow
  asserts a direction; the default view's interval `[-$0.029911, +$0.303415]` does not support one.
  Source scan: `delta=` absent.
- **`st.metric(help=…)` is FORBIDDEN.** `help` renders as a hover tooltip, invisible in a screenshot,
  which is exactly the failure D-07 exists to prevent (06-RESEARCH Pattern 4, verified against
  `streamlit/elements/metric.py:111`).
- **`st.metric(border=True)` is FORBIDDEN.** Two bordered metrics would split the pair D-03 says *is*
  the argument into two boxes. One `st.container(border=True)` holds both.
- **A subheader never carries a number.** Section headings name the question; numbers live in metrics,
  markdown and tables where the caption rule reaches them.

result is statistically detectable.** `st.success`, `st.warning`, `st.info` and coloured badges are
FORBIDDEN. `st.error` is permitted for the artifact-load failure path only (see
`## Copywriting Contract`). Source scan: `st.success(`, `st.warning(`, `st.info(`, `st.badge(` each
occur 0 times.

The reason is measured, not stylistic. At the pre-registered `k = 0.20`:

|---|---|---|
| `uplift_womens_visit` — **shipped** | `+$0.101593` [`-$0.029911`, `+$0.303415`] | covers zero |
| `uplift_womens_conversion` — **sensitivity, not adopted** | `+$0.160179` [`+$0.003802`, `+$0.323909`] | excludes zero |

weight in both states**, never by colour.

## The Core Design Problem, Resolved

The app's default view shows a positive number the data cannot distinguish from zero. A ten-second
read and an honest read are in genuine tension. This contract resolves it as follows, and the
resolution is the reason the layout below is ordered the way it is.

**The ten-second payload is a decision sentence, not a number.** The first content under the title is
one bold line stating what to do. A recommendation about an *action* needs no confidence interval, so
it can be read in two seconds without being incomplete. The dollar figure — which the ROADMAP goal
also requires on the first screen — follows immediately, and is never permitted to travel without its
interval and its verdict line.

**Both detectability states use the same artist at the same visual weight and differ only in
wording.** Not-detectable is not demoted: 05-08's approval says "the fact that it is hatched across
most of its range including at the anchor is the point, not a weakness." Detectable is not promoted,
for the measured reason in `## Color` above. One bold markdown line, same position, same weight,
three possible texts.

**Three verdict states exist, not two.** Pinned verbatim; the app selects among them from the band
row's `lo`/`hi` alone:

| State | Predicate | Verdict line (verbatim, bold) |
|---|---|---|
| covers zero | `lo <= 0 <= hi` | `**Not detectable at this depth:** the 95% interval includes zero, so this data cannot distinguish this from no gain at all.` |
| excludes zero above | `lo > 0` | `**Detectable at this depth:** the 95% interval lies entirely above zero.` |
| excludes zero below | `hi < 0` | `**Detectably worse at this depth:** the 95% interval lies entirely below zero — targeting this deep does worse than a random send of the same size.` |

The third state is **reachable and was nearly missed.** On the shipped ranking's spend contrast at
`k = 0.99` the band is `[-$0.197415, -$0.006580]` around a point estimate of `-$0.088285` — one depth
of 101 (read from `policy_bands.parquet` / `policy_curve.parquet`, 2026-09-10). Without a third state
the app would print a negative number under a line reading "the interval excludes zero", which reads
as good news.

**The predicate must be the figure's predicate.** `lo <= 0 <= hi` is exactly the condition
`policy_curve_plot` hatches on. The state must be computed from it and never from the sign of the
point estimate, so the app's words and the figure's hatching cannot disagree at any of the **404**
published (ranking, outcome, depth) rows the app can display — 2 published rankings x 2 displayed
outcomes (spend and visit; conversion is not surfaced, per D-03) x 101 depths. Measured from
`policy_bands.parquet` on 2026-09-10: the `delta_random` rows for those rankings and outcomes number
exactly 404, 101 per (ranking, outcome) pair. **The test must sweep the artifact's own rows rather
than hard-code this count**, which is why V5 is written that way; the figure is stated so a reader
knows the intended scope.

#### Headline-block hierarchy — *(added 2026-09-10, 06-07 checkpoint)*

The reviewer read 3.3–3.6 as "four undifferentiated text lines": the revenue figure, its interval,
its verdict and its explanatory caption. Two changes discharge that, and **no word of copy and no
number moved** — both are changes of artist and of emphasis only.

- **3.1 is bold on its lead alone.** A three-line sentence set entirely in bold was the loudest
  thing on the first screen and was competing with the two numbers it exists to introduce.
- **3.2 is a caption.** It is an instruction about how to read what follows, which is what the
  caption artist is for; demoting it leaves the metric as the only heavy element between the
  recommendation and the curves.

Six children now carry four weights top to bottom: bold lead, quiet caption, metric, plain interval,
bold-lead verdict, quiet caption. `st.columns` and `unsafe_allow_html` were **not** available for
this and that constraint is load-bearing rather than bureaucratic — D-07's adjacency is asserted by
index over flat document order, so 3.3/3.4/3.5 and 3.7/3.8/3.9 must stay consecutive children. Both
changes sit outside those two triples and the index walk is untouched.

## Numbers Discipline

*(Amended 2026-09-11 — the two display formats move from **six decimals to three**. The original
pinned `"$" + f"{v:+,.6f}"` → `+$0.101593` and `f"{v:+.6f}"` → `+0.006165`, described below as
"chosen to match `reports/policy.md` §5 digit for digit". The reason for the change: the headline
figures were printing six decimals on quantities whose 95% intervals span roughly `-$0.03` to
`+$0.30`. That is precision the data does not support, and it reads as false confidence to exactly
the reviewer this app is written for. Three decimals is the grain the evidence supports.*

*The scope is **the app only**. `reports/policy.md` §5 keeps its six decimals — it is the checkable
record and keeps every digit it computed, while the app is the reader-facing surface. The two
documents therefore print one quantity at two precisions **by design**, and that divergence is the
decision rather than a defect to reconcile. The consequence for the verbatim test below is set out
in its own amendment.*

*One note disarming the rest of this file: the six-decimal strings elsewhere in this document — the
Q1 worked-example table above, the shipped-cell row in the model-results table, and the "Every number
in this contract" provenance table below — are **artifact values as read**, not display strings.
They are deliberately left exactly as they were read on 2026-09-10. No number in this document is
recomputed by this amendment.)*

**The app performs no arithmetic on any displayed number.** Every value is read from an artifact
column and formatted. Checkable by source scan: no `* 100`, `100 *`, `/ 100`, and no unit conversion
anywhere in the app module. This is why the visit contrast is displayed as the raw rate `+0.006`
— the same grain `reports/policy.md` §5 prints, at this app's coarser precision *(Amended
2026-09-11 — was "the raw rate `+0.006165` exactly as `reports/policy.md` §5 prints it". The
raw-rate claim survives unchanged and is still enforced; only the "exactly as §5 prints it" clause
is withdrawn, because the app now rounds and the report does not. Rounding changed the grain of the
digits, never the unit.)* — even though the figure directly beneath it uses
percentage points on its y axis — `plots.py` owns that scaling through `_UNIT_SCALE`, and the app
reproducing it would be a second place the grain could be wrong.

Pinned display formats:

| Unit | Format | Example |
|---|---|---|
| `$` | `"$" + f"{v:+,.3f}"` | `+$0.102` *(Amended 2026-09-11 — was `,.6f` / `+$0.101593`. See the note above.)* |
| rate (`pp` column, displayed raw) | `f"{v:+.3f}"` | `+0.006` *(Amended 2026-09-11 — was `+.6f` / `+0.006165`. See the note above.)* |
| capacity | `f"{k:.0%}"` | `20%` |
| counts | `f"{n:,}"` | `4,269` |

**A test this enables, and it should be written:** at first paint every numeric string the app renders
is **either** a string `reports/policy.md` carries verbatim **or** the three-decimal rendering of a
number `reports/policy.md` carries. The app cannot contradict the evidence document in its
most-screenshotted state: it may print a quantity at coarser grain than the report, but it may not
publish a quantity the report does not carry at any precision. **Still not a tolerance** — there is
no epsilon, and every displayed string is matched against a specific report number, either as its own
string or as that number re-rendered through the pinned formats. *(Amended 2026-09-11 — the original
read "appears **verbatim** in `reports/policy.md` … and the check is a substring search rather than a
tolerance". The verbatim-only rule was correct while the two documents shared one convention; the
second arm is what accommodates the rounding above without weakening the check to a tolerance.)*
