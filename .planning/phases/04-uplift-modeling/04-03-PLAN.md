<objective>
Materialize D-07's `split` column: restructure `ingest.build_all` from four gates to five, regenerate
the three committed Parquet artifacts with the column present, and move every affected shape
assertion with them.

Purpose: ROADMAP criterion 1 requires the split to be "materialized as a column in the processed
table" so that a later phase is *physically unable* to use a different one. A seed shared between two
functions is a convention; a committed column is a fact. This is ARCHITECTURE Pattern 5's entire
point and it is why the scored artifact can later be holdout-only in a way no downstream consumer can
undo.

**This is the riskiest plan in the phase**: low code volume, high blast radius, and the only plan
that can break a green Phase 1 and Phase 2 suite. It owns its own wave for that reason. Per
04-VALIDATION.md §Sampling Rate, **every task in this plan verifies suite-wide, never with a module
subset** — a module-scoped run would miss exactly the cross-file breakage this plan is most likely to
cause. Task 1 runs `pytest -q -m "not slow"`; Task 2 runs `pytest -q --ignore=tests/test_artifacts.py`,
the one deliberate exclusion, because that file's reds are the artifacts Task 3 regenerates; Task 3
runs the unrestricted `pytest -q` and the plan's acceptance gate adds `-m slow`.

Output: a five-gate `build_all`, updated shape assertions in two test files, and three regenerated
committed artifacts.
</objective>
