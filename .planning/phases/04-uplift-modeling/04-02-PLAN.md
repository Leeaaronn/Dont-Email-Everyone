<discretion_resolutions>
- **Four new factories, not an extended `qini_plot`** (04-RESEARCH §Q6). Three concrete reasons:
  `qini_plot`'s dashed baseline is the computed chord to `qini[-1]`, and two curves means two chords,
  which `test_qini_plot_chord_is_computed_not_diagonal` asserts against by introspecting the drawn
  `Line2D` objects; `qini_plot`'s y-limits are computed from a single curve and
  `test_qini_plot_x_limits_are_pinned` and its siblings assert that; and ten `qini_plot` tests pass
  today, so a new factory leaves all ten untouched while a new parameter puts all ten at risk for
  zero benefit.
- **`plots.py` is the home, not a new module** (02-05, 03-03, and CONTEXT's Claude's-Discretion
  section, which says so outright). `plots.py` already sets `matplotlib.use("Agg")` on the line
  immediately before the pyplot import and
  `test_plots_module_selects_the_headless_backend_before_pyplot` asserts that ordering; a second
  module importing pyplot would need a duplicate of that line, and the duplicate is the one someone
  eventually deletes.
- **The calibration plot panels by unit, following `ate_forest`.** Six cells whose effects span three
  orders of magnitude (0.003111 to 0.769827) cannot share one numeric axis — `ate_forest`'s docstring
  records the identical finding: a shared axis would draw the +$0.77 spend effect as though it were
  76.98 percentage points.
- **No PNG is committed by this plan** and `FIGURE_NAMES` in `tests/test_reports.py` is not touched
  here. Plan 04-08 extends it in the same plan that writes the files, so an added name and an added
  file can never diverge.
</discretion_resolutions>
