<objective>
Have `pipeline.train()` write the curated committed figure set, extend `FIGURE_NAMES`, and commit the
PNGs.

Purpose: ROADMAP criterion 3 requires train and holdout Qini "plotted on the same axes for every
model", and D-23 names five kinds of figure the phase must leave behind. Phase 3 deliberately
committed no figure — 03-06 recorded that a synthetic Qini curve sitting beside the real
`love_plot.png` and `ate_forest.png` could be misread as a result, and that the first committed uplift
figure would be Phase 4's, drawn on real holdout scores. This plan is where that lands.

The single most convincing image this phase can produce is the permutation-null histogram for the
default RandomForest on mens/visit, with its observed holdout Qini marked **inside** the null, beside
its own spectacular train curve. It is the whole argument for holdout evaluation in one figure, and
D-14 exists to make it possible. Figures are kept separate rather than composite precisely so Phase 7's
README can embed that one on its own.

This plan carries a **human-verify checkpoint**: figure legibility is not machine-checkable beyond a
byte floor, and 04-VALIDATION.md lists it as one of the phase's two manual-only verifications.

Output: figure writes in `train()`, the `FIGURE_NAMES` extension, the figure assertions, and the
committed PNGs.
</objective>

  renders nothing, so a later phase can reuse the same factory in a different output context. An
  unclosed figure stays registered in pyplot's global state for the life of the process, and
  matplotlib warns once more than twenty accumulate — which a ten-figure run plus Phase 2's two is
  close to.

- **Write each figure as an explicit `savefig` / `plt.close` statement pair, not in a loop.**
  `tests/test_pipeline.py:379-381` asserts `body.count("savefig(") == body.count("plt.close(") == 2`,

  change the assertion to equality between the two counts without the literal and record the reason in
  the test's comment — but explicit pairs are strongly preferred because they keep the count
  meaningful.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-memory results → the committed PNGs | The publication boundary. These images are what a reviewer looks at first and what Phase 7's README embeds. |
| `plots.py` factory → `pipeline.py` write | The lifecycle boundary. The factory returns a Figure; the orchestrator owns both the write and the close. |
| `FIGURE_NAMES` → the files on disk | The coverage boundary. An allowlist, not a glob — a figure absent from the list is untested. |
| the committed figure → the reader's conclusion | The reputational boundary, and the one this plan's checkpoint exists to guard. |
