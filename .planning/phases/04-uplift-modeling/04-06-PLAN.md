<objective>
Add the refit permutation null to `dont_email_everyone/models.py` — the mechanism D-04's ship rule
turns on — with its fast and `slow`-marked tests.

Purpose: ROADMAP criterion 3 requires that "a model whose Qini sits inside the null distribution is
reported as such rather than shipped as a result". That sentence is only enforceable if the null is
generated by the same procedure as the observed value. D-15 chose the **refit** null over the
near-free evaluation-only shuffle for a stated reason: an evaluation-only null tests a strictly weaker
hypothesis and cannot detect a model that overfit the treatment label during training — which is
exactly the failure PITFALLS Pitfall 4 names and exactly what D-14's unbounded-forest exhibit depends
on catching.

The compute question is settled: the full eight-cell suite at R=200 measures at **~6.4 minutes
single-threaded**, of which the six primary linear cells account for **25.5 seconds** [MEASURED,
04-RESEARCH §Q1]. The CONTEXT's "cut null scope if impractical" contingency is not needed and this
plan does not budget a branch for it.

Output: the null generator, the p-value helper, the cell list and the summary shape in `models.py`,
plus their tests. **The committed null artifact is plan 04-07's** — `pipeline.py` is the only writer.
</objective>

<discretion_resolutions>
- **The `slow` test regenerates ONE linear cell at full R=200 and asserts it reproduces bit-for-bit**
  (04-RESEARCH §Q1, option B). Cost: **+5.5 s** [MEASURED]. The alternatives were rejected with
  numbers: regenerating all eight cells at R=200 adds 6.4 minutes to a `-m slow` suite that is
  currently 14 tests beside a 40-second full run — a tenfold increase in the heavy suite for a check a
  committed artifact already encodes; and regenerating all eight at a reduced R proves nothing
  bit-for-bit, because a reduced R consumes a different prefix of the same stream only if the loop is
  written to allow it. Option B is the strongest possible statement about the generator at 1.4% of the
  cost, paired with the fast unmarked test D-18 already specifies.
- **One RNG stream per cell, seeded from cell identity** — this is what makes option B possible and it
  is the one place `models.py` must NOT copy `coverage.py`. `coverage.empirical_coverage_table`
  consumes one stream across the whole grid, and 02-05 recorded the consequence: a one-off single-cell
  call returns a slightly different result than the same cell inside a full sweep. That was acceptable
  there because nothing regenerated a single cell. Here something does.
- **`PERMUTATION_SHUFFLES = 200` is a separate literal from `evaluation.NULL_BAND_RESAMPLES`, which is
  also 200** (04-RESEARCH §Q6). They are different quantities that happen to agree today; importing one
  as the other means a future change to either silently changes both.
- **`(1 + count) / (1 + R)`, not `count / R`** (04-RESEARCH §Q5 subtlety 3). The plain form can return
  exactly `0.0`, and a reported `p = 0` from 200 draws is an overclaim — the correct statement is
  `p <= 1/201`. The `+1` in both numerator and denominator amounts to including the observed value in
  its own reference set, which is the standard valid Monte-Carlo construction (Davison & Hinkley 1997;
  Phipson & Smyth, *Permutation P-values Should Never Be Zero*, SAGMB 2010).
- **The percentile gate and the p-value are two different tests and both are reported.** D-04's ship
  rule turns on `Q_observed > np.quantile(draws, 0.95)` over the 200 draws only, not including the
  observed value. They can disagree by one draw at the boundary; in this repo they agreed in all six
  primary cells [MEASURED]. The report must state which one the ship rule uses and must not let a
  later agent substitute `p <= 0.05` for the percentile.
- **`n_jobs` stays a literal 1 inside the null loop.** `n_jobs=-1` would cut the suite from ~6.4 to
  ~2.5 minutes but emits a `UserWarning` on this version and makes the committed null artifact
  thread-count dependent through floating-point reduction order.
</discretion_resolutions>
